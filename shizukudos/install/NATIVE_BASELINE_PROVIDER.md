# Independently launch-owned live baseline custody

This module provides a concrete Linux keeper/client path. Source custody and
fixed Win98 observation are useful and separate from independent private lineage
approval. It never issues Windows/source approval from a SHA, JSON, receipt,
Win9x4.10 result, successful arbitrary process or callback predicate. WINDOWS_GRADE
always refuses until the root-owned private live lineage authority is connected.
No policy/ingester source is changed here. Original Microsoft DOS control is
never labeled Windows on ShizukuDOS, default GOP, SE certainty or key application.

`Client(source_pin, fresh_owned0700_directory, control_request=None,
borrowed_launcher=None, owner_unit=None)` internally starts its exact reviewed provider script
with a pinned canonical Python executable using -I. It owns actual Popen/pidfd,
checks actual argv/interpreter inode, and accepts one post-exec connection in
its new private SOCK_SEQPACKET listener. SO_PEERCRED PID must equal this actual
child; retained pidfd detects its death. The service independently verifies the
listener creator PID and its actual parent PID. A new owner-random handshake
and fresh32B per-request challenge plus exact sequence prevent saved-response
reuse. Packets are bounded64KiB. Guest remains≤600s and the observation phase≤900s. Total keeper lifetime is
bounded5400s from actual owner creation; after a successful reaped observation,
the root-owned compiler hold is min(total deadline, observed time+4500s). It is
started exactly once and cannot extend an expired guest/observation phase.
A prefork socketpair/sameUID/caller-selected PID cannot identify the child.

Without control_request, source-only keeper holds actual owned0400 regular
nlink1 original source and actual read leases/fullSHA of provider/interpreter/
configuration inputs. This mode is for Linux source-custody controls and always
reports SOURCE_CUSTODY_ONLY. It cannot substitute for Windows execution.

With the exact independently reviewed private control_request, the service
calls only the fixed actual control.run implementation. That implementation
owns freshFICLONE, fresh nonce, source-built Win98 observer, sole actualQEMU/QMP,
explicit desktop-reviewed Run, actual reap, exact guest VFAT JSON readback and
full original/clone/producer hashes. A minimal optional retain hook receives a
nonserializable OwnedObservation only after those steps, while the same original,
reaped-clone and producer FD read leases remain active. The hook only serves
challenges/lifetime; its return never supplies identity or changes grade. On
release, original/clone/producer fullSHA checks repeat before lease teardown.
The keeper publishes SOURCE_AND_OBSERVATION_CUSTODY_ONLY and hashes the observed
report/version/count rather than exporting a whole registry. No fixed Windows
route has been executed by the Linux tests or this module's source work.

`wait_ready()` waits for actual held source or observation. `query()` challenges
the live exact keeper. `match_held_source(entry)` compares actual compiler FD
kernel identity, RDLK and fullSHA with the live keeper source. `finish()` requests
full keeper readbacks, waits for actual childexit0/reap, then checks launcher
input hashes. A saved summary is reporting, never a capability. The Client is
process/thread/lifetime-bound and cannot be serialized. Cancellation, child
death, peer EOF, wrong token, reused challenge/sequence, inode/namespace drift,
lease break, wrong compiler FD or failed final readback refuses and revokes it.

Standalone parent launcher owns one read-lease union. In a production build
which already owns native_payload_ingest.Union, pass that actual source-admitted
union as borrowed_launcher. Provider/interpreter/configuration inputs are added
to it; no new SIGIO handler is installed, and its FDs are never closed by Client.
Raw actual FD/identity/lease checks avoid recursion if the caller adds a provider
challenge guard to the union. Root must source-admit the actual ingester and
provider origins; a duck-typed JSON object is not an approved union or authority.
The existing ingester union and policy remain root-owned. Private request,
source pins, original media lineage, observer output/images and keys stay private.

Next root integration interface is a live Client retained through the existing
compiler callback: check actual held source FD, append a live provider guard,
finish/reap before release. The remaining approval premise is independent root
approval of real media-to-install lineage, retained as live private state and
matched to this keeper's exact original source and observed clone. That state
cannot be requested from a caller-provided approval dict or an old fixture.
No mandatory invented issuer stack or new saved approval schema is introduced.
Root policy must continue refusal until this independent premise is implemented
and tested with actual original Win98 fresh nonce observation. Historic raw-disk
identity is a control input, not license/SE/key proof by itself.

Controls execute real Linux AF_UNIX postexec credentials, Popen/pidfd, RDLK/fullSHA,
source/tool paths, conflicts/aliases, replay and borrowed ingester union lifecycle.
They use tiny explicitly synthetic offline original fixtures, no QEMU/Win98/VM.
Existing actual observer C uses modeled Win32 controls only; actual Windows and
QEMU ownership must be evaluated separately in the reviewed private trial.

Windows keeper mode requires an actual independently owned delegated owner_unit
whose MainPID is this launcher, Delegate=yes and RuntimeMax=infinity. It creates
a new owned descendant cgroup and moves only its newly forked Popen there before
exec. Postexec peerPID still matches this actual child. No attached PID or global
cgroup is used. Cancellation first lets the keeper run its actual cleanup. After
12s the launcher may TERM/KILL only its observed own descendant group members;
it never SIGKILLs the keeper while another live descendant exists or an actual
direct child remains unreaped. Source/clone inputs remain held during that wait.
Cleanup may outlive phase expiry until actual quiescence; source-only mode retains
its separate3s cancellation grace. Long-child tests use actual independent Linux
delegated test units and explicitly modeled pre-OBSERVE phase, no QEMU/Windows.
