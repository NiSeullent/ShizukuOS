# Explicit assignment of the outer VM's std-VGA

This optional path assigns the isolated outer QEMU VM's actual std-VGA device to the native Windows 98 domain. Guest VGA registers, DAC, planar latches and framebuffer contents are supplied by that device. The Supervisor does not render a substitute Windows desktop. No Linux host physical device is accessed by the host tests.

The normal profile remains unchanged when `win98_vga` is absent or `no`. To request this path, BOOT.INI must explicitly contain `mode=supervisor` and `win98_vga=yes`, the existing installed-Windows `WIN98CFG.BIN` must be valid, and both `SHZDOS/VGACFG.BIN` and `SHZDOS/VGAROM.BIN` must exist. Switching the boot menu away from Supervisor refuses the VGA request. A missing, duplicate or malformed requested input fails admission.

VGACFG is a separate 136-byte little-endian record; existing W98 config and shz_info ABIs are unchanged. Its fields, in order, are six u32 values (`magic=0x41475657`, `version=1`, `bytes=136`, `flags=1`, observed bus-zero BDF, `reserved=0`), two u64 values (actual observed/admitted L1 BAR0 base and exact 16 MiB extent), and three 32-byte digests (padded-ROM SHA256, producer-source identity, producer-config identity). The BDF/base/extent must come from the explicitly bound QEMU recipe and actual read-only observations. They must not be manufactured from default device settings. Source/config digests identify inputs; their presence does not replace the actual independently reviewed source-built firmware receipt.

VGAROM is an independently source-built x86 std-VGA option ROM padded with zeros to exactly 64 KiB, page-aligned by the loader. Admission checks its complete SHA256, 55AA header, bounded image and PCIR structure, checksum, x86 code type, final-image bit, display-VGA class and 1234:1111 identity. The Supervisor's synthetic reset-vector `vbios.bin` is a different artifact and is not accepted as this VGA ROM.

Only one observed bus-zero display function may exist; it must match the explicit std-VGA binding with I/O and memory decode already enabled. Read-only L1 config transactions save/restore CF8 and never write CFC or size live BARs. The guest sees only this function through a private CF8/CFC shadow; all other BDFs float high, including the Supervisor-owned storage function. BAR0 exposes only the admitted 16 MiB LFB and the ROM BAR exposes only the immutable 64 KiB ROM. Other BARs, capabilities, bus mastering and interrupt advertisements remain absent. SeaBIOS's BAR probes, aligned byte/word/dword config accesses and allocations are handled in the shadow. Relocation revokes the previous guest mappings; no guest config write moves an L1 BAR. Allocation spans are bounded outside guest RAM and below FEC00000, and may not overlap each other.

Before any device mode programming, host paging selects an actual inherited PAT UC slot for 4 KiB identity leaves covering A0000–BFFFF and the exact LFB. It never rewrites global PAT or unrelated leaves. Every Supervisor GOP renderer entry is permanently excluded before DISPI mode disable/readback. Native worker bootinfo already withholds GOP fields; serial output remains available. Failed transfer keeps renderer exclusion and never publishes a runnable new VMCS.

L2 aperture/LFB mappings are UC and writable without execute permission; the ROM is read-only. A20 changes update the low aperture alias and the LFB's folded 1 MiB blocks, and revoke/restore ROM aliases consistently. String-I/O physical translation and scalar guest EPT mappings use the same admitted backing. Failed port callbacks stop before operand writes, counter/register or RIP advancement. Passive fault tracing refuses device reads because real VGA reads can modify latches.

Host tests execute the actual native port/physical/A20/constructor, renderer, PCI policy and host page-table bodies with privileged boundaries modeled. They include valid synthetic ROM fixtures with known full hashes, malformed ROMs whose checksum/hash are recomputed, old-code RED controls, failure cleanup and strict GCC/Clang sanitizer controls. Anonymous constructor fixtures reserve a 2 GiB address range without making a disk copy; their tiny modeled media and VMCS calls are not boot evidence. The ordinary component compile verifies linking and EFI construction only; its synthetic DOS vBIOS is not genuine VGA firmware provenance.

Actual nested MMIO operation, installed display-driver selection, Windows VMM/GDI/Explorer, native applications, persistence, SMP and public ISO acceptance all remain unverified. The current native ESP producer does not yet accept the extra VGA inputs/receipt; production VGA launch remains ineligible until its separate source-bound input producer, real recipe/device admission and runtime tests are complete. Existing baseline media is not relabeled or modified.
