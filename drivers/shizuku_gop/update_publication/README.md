# Private publication candidate

This opt-in source candidate prevents the frozen SHZGOP timer from publishing inside a matched BeginAccess/EndAccess operation and prevents the completing copy from erasing newly queued damage. It does not establish the cause of the observed white desktop icons. Native acceptance remains pending and application success remains false.

The only changed private driver sources are vxd_vesa.c, vxd_wram.c, and wram.h. The default builder, current backend, old compiled package, NE DIBEngine imports, fixed firmware mode, descriptor wire contract, and installed image are unchanged. The builder requires the exact original source ZIP and object closure and reproduces the old VXD before compiling the candidate. It writes only a new output directory and never stages or launches a VM.

The candidate increments a private 32-bit nesting depth before marking damage, including empty clipped rectangles. Matching EndAccess decrements it; unmatched EndAccess or depth saturation latches publication off until initialization. This is a defensive failure state, not a claim that valid Windows metadata is corrupt. Pending dirty state is a boolean with bounded rectangle union; it cannot overflow the upstream increment. The publisher detaches an immutable rectangle descriptor before the copy. An inflight guard refuses recursive publication. New damage remains in the live descriptor for the next timer. When timer initialization failed, synchronous publication performs at most two copies so one interrupted copy receives a follow-up without an unbounded drain. Additional interruptions preserve pending damage for the next EndAccess or explicit draw; eventual repaint under continuous changes without a functioning timer is unsupported. The old semaphore helper is not used by the candidate access callbacks or publisher.

Ring-0 helpers save and restore caller EFLAGS while briefly masking maskable interrupts around metadata and a bounded 8,212-byte static cursor snapshot. The framebuffer pixel copy runs with caller flags restored. The snapshot is static to avoid growing the kernel stack. Its dimensions are checked against the actual fixed 32x32 mask arrays; signed position overflow is avoided with unsigned bounded differences. An invalid cursor shape draws no cursor but still publishes framebuffer pixels. Existing cursor-load admission and other upstream cursor routines are outside this patch; the candidate does not claim to repair all malformed cursor inputs.

The supported execution model is the existing Win98 single CPU ring-0 callback path: the memory-only blitter has no yield, wait, allocator, VMM callback, or GDI call. Ordinary Win16 drawing therefore cannot run during that timer copy; a hardware cursor callback may interrupt it, and its completed mask/state update queues the next repaint while the current copy uses its own cursor snapshot. This is not an SMP lock or support for an independently scheduled framebuffer writer. Actual callback context, EFLAGS restoration, interrupt latency, guest painting, and the loaded driver identity still require private native evidence and root review before staging.

Host controls mechanically extract the actual baseline and candidate access, publication, mode, pixel, async initializer and timer callback functions. Interrupt primitives and VMM clock/timeout services are replaced with a deterministic delivery model; the actual pixel loop has entry counting and an after-read delivery hook. The real async initializer returns failure when the modeled timeout service fails. Baseline controls reproduce premature publication, lost new damage, ineffective nesting, and mixed cursor masks. Candidate controls check final pixels, nested and empty access, clipping, dirty union, reentry, cursor changes, overflow/underflow, disabled publication, caller flags, clear/mode behavior, one fallback follow-up, and retained damage if that follow-up is interrupted under normal GCC and Clang ASan/UBSan. Host pointer layout is not native ABI proof; the real i486 object build and frozen disassembly are separate evidence.

Run only after source/build authorization:

    python3 drivers/shizuku_gop/update_publication/build.py --out build/shzgop-publication-CANDIDATE-UNIQUE

The primary compiler contract is the [Open Watcom auxiliary pragma guide](https://open-watcom.github.io/open-watcom-v2-wikidocs/cguide.pdf): the assembly helpers do not declare nomemory, so they retain the compiler's conservative memory effects. The actual emitted instruction ordering is frozen for review. Current evidence and screenshots are pinned through the separate read-only investigation receipt.
