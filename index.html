02 / SETUP GUIDE

설치 방법

직접 빌드한 DLL을 기존 Windows 98 SE 시험 VM에 연결하는 절차입니다. 설정을 바꾸기 전에 VM과 core.ini를 백업하세요.

01

시험 환경 준비

사용 권한이 있는 Windows 98 SE 설치 미디어로 시험 VM을 만듭니다. 이 프로젝트가 확인한 VirtualBox 환경은 BIOS/IDE, CPU 1개, RAM 128 MiB였습니다. 다른 하드웨어 구성의 동작은 별도 검증이 필요합니다.

별도 준비
02

Unicode Layer와 KernelEx 설치

게스트에 Microsoft Layer for Unicode를 먼저 설치해 C:\WINDOWS\SYSTEM\UNICOWS.DLL을 준비합니다. 이어 KernelEx 4.5.2 ↗를 설치하고 재부팅합니다.

Microsoft Layer for Unicode 배포 기록 ↗

게스트
03

DLL 빌드

Windows 호스트에 Python과 32비트 LLVM MinGW의 i686-w64-mingw32-gcc를 준비합니다. 프로젝트 루트에서 아래 명령을 실행하면 build\m98wrap.dll이 생성됩니다.

PowerShell_ □ ×
python -m pip install -r tests/requirements.txt
.\build.ps1
호스트
04

KernelEx에 연결

m98wrap.dll을 게스트의 KernelEx 설치 폴더에 복사합니다. 같은 폴더의 core.ini에서 기본 contents=std,kexbases,kexbasen 줄 끝에 ,m98wrap을 추가한 뒤 재부팅합니다. 설치본 설정이 다르면 파일 전체를 덮어쓰지 말고 해당 줄만 편집하세요.

게스트
05

동작 확인

빌드된 smoke.exe와 import_probe.exe를 시험 VM에서 실행해 래퍼와 KernelEx의 정적 import 경로를 확인합니다. 프로젝트의 기존 128 MiB VM에서는 두 시험이 통과했습니다. 새 환경에서는 결과를 다시 확인해야 합니다.

검증됨 / VERIFIED37 APIs

KernelEx 래퍼

Windows 98 SE 시험 게스트에서 최신 DLL의 37개 직접 호출 시험을 통과했습니다. 설치된 KernelEx 설정의 정적 import 시험은 이전 29개 빌드에서 통과했습니다. 일부 함수는 제한적으로 구현됐습니다.

개발 중 / IN PROGRESSDOS prototype

ShizukuDOS

독립 부팅, FAT12 읽기, 제한된 COM 실행과 체인로드를 시험했습니다. Windows 98의 GUI 부팅을 대체하지는 못합니다.
