# ShizukuOS production implementation

Read workspace AGENTS.md, docs/SHIZUKU_HYBRID_TRANSITION.md and docs/SHIZUKUOS_FULL_GOAL_ACCEPTANCE.md. Use ShizukuCore -> DOS(SZRm), 32(SZPrtm), 64(SZLm), OS(Windows98); gradual independent kernel and actual Windows98 userland/code. Preserve current backends and source ownership.

Implement real production callers, providers, exports and build integration. A disconnected helper or successful placeholder does not establish a working driver or application. Validate pointer/length arithmetic and generation-bound resource lifetime; deny absent authority truthfully. Preserve old strict installation profiles when adding a distinct explicit phase. Never infer release authority from a JSON claim or saved receipt. Windows x64 and SystemV have different ABIs; kernel code has no red zone. Preserve external code provenance and licenses.

Use many independent useful coding agents, disjoint source writers and serialized shared-index commits. Route complex kernel/install/authenticated protocol and app-port work to Opus5.5; bounded adapter, test and documentation work can use Sonnet5.5. Select effort according to complexity. Generate code first, compile affected actual translation units and small meaningful regressions, then coordinate one current integrated VM cohort. Avoid repeated full suites or large synthetic disk fixtures without a new reason. Preserve actual failures.

Prioritize a bootable installable64-bit OS with real recognized drivers; all fifteen goals and Chromium/Legcord/Office/Steam remain mandatory. Keep `.codex/task-state.md` for long work. Do not mark component tests as guest/app/install acceptance. Never publish Windows media, guest disks or credentials. Final ISO goes through nginx m98.nyase.kr only after release gates pass.
