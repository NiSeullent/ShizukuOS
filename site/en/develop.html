Development and source

The foundation of ShizukuOS itself.

ShizukuOS is the operating system itself. We are extending ShizukuOS Core and the existing Korean executable shell, connecting themes, sound, drivers, apps, Linux Subsystem and virtualization. The features below are targets awaiting implementation and execution verification.

An architecture rooted in ShizukuOS

ShizukuOS is the root platform. ShizukuOS Core contains ShizukuDOS, the Kernel Layer and the Driver Layer, connected to ShizukuVM, Linux Subsystem and Native Runtime. The structure below requires implementation, integration and actual execution verification.

ShizukuDOS

DOS Mode, Protected Mode, Long Mode and v8086 execution environments. Existing implementations are inspected and extended without duplicate components.

Kernel Layer

Connects Kernel32, Kernel64, SHZLB.sys and VM Services. Resource authority and lifetime follow ShizukuOS service contracts.

Driver Layer

Layers Native, Legacy and Wrapped drivers. Standard ACPI, PCI/PCIe, USB, storage, networking, audio and display hardware are priorities.

Native Runtime

The foundation for the OS's own shell and apps, built, packaged and executed as ShizukuOS binaries. Windows 10 x86/x64 API compatibility is a target requiring real behavior.

An executable shell and data-driven themes

Extend the existing native shell and reuse license-compatible components. Slade is the default theme target, alongside clean Flute and experimental Jade. Theme definitions should control windows, typography, icons, buttons, menus, effects, animations, wallpaper, cursors and sound.

Startup, shutdown, login, notifications, errors and device events require system sound. Implementation must check available existing sound sources first. Complete theme and sound behavior remains unverified.

ShizukuVM and Linux Subsystem

ShizukuVM defines the OS's own VM API and kernel virtualization services. Linux Subsystem is a Core component connecting a Linux-kernel sandbox and POSIX environment through SHZLB.sys. Initial chkrnl /mode linux and chkrnl /mode msdos modes require kernel-supported execution environments.

ShizukuLB — Shizuku Linux Basebuild uses Nix for packages; pkgs operations synchronize with that Nix environment. Linux X sessions should pass through SHZLB.sys and Shizuku Window Bridge into ordinary managed desktop windows. Completion of this path remains unverified.

Native baseline application targets

Terrasphere

A lightweight native WebKit browser targeting usable browsing and a modern interface.

Muzik

A music and video library application with metadata, playlists and visualization.

Sapphire

Lightweight photo viewing, with image editing and drawing loaded when needed.

Folio

Reuse existing open-source document processing and adapt its interface to the ShizukuOS family.

Each application requires an executable path and real functionality verification. Names and UI demonstrations do not establish completion.

Acceptance criteria for 1.0.0

Actual ShizukuOS execution must verify stable boot, drivers, shell, customizable themes, sound, networking, filesystems, apps, browser, media, graphics, Linux Subsystem, virtualization and games. The installer, two cold boots, security and clean exits also require verification. Kernel boot or historical captures do not establish completion; final acceptance remains incomplete.
