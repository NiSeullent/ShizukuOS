# Opt-in Windows 98 domain integration plan

This is an implementation step for ShizukuDOS, the intended MS-DOS replacement foundation for Windows 98. Kernel32 and Kernel64 belong to that foundation. A Supervisor Windows domain and a functioning channel are prerequisites; neither is completion of DOS→VMM replacement, Windows GUI, acceleration or current apps.

1. Port the preserved actual ATA PIO, bounded REP PIO/386 paging and Win98 VMCS constructor into `shizukudos/supervisor/native_win98/`. Keep their provenance. Integrate the reviewed loader, domain, IRQ/PIC, CR2 and scheduler seams into the current source. The normal DOS10 path remains selected without an explicit valid 16-byte WIN98CFG.BIN.
2. Keep Win98 low memory owned by its real BIOS/DOS. Map its channel but never write Shizuku bootinfo at 0x7000. Let its VxD discover CHANNEL_INFO. Select K32 interkernel tests only when the real K32 peer exists; a Windows-only K64 channel is not that peer.
3. Replace the historical private builder with ordinary source-bound compilation and explicit disk/ROM/config inputs plus required SHA-256. Require a regular, stable, non-symlink input, exact 2 GiB disk/256 KiB ROM/16-byte versioned config, owned output and bounded preparation space. Copy/compile only into a new output directory. Optional caller-supplied kernel/runtime files carry independent hashes. No default private paths, source downloads, host disk formatting or VM launch.
4. Run the actual C ATA/paging/PIC/constructor bodies under strict GCC and Clang ASan/UBSan; callbacks model EPT/VMCS and the tests do not execute VMX. This host's GCC sanitizer runtimes are absent, so no GCC sanitizer pass is claimed. Verify valid/malformed config, refused paths/hash/geometry, stable private copies and no-success-on-incomplete-output behavior with host fixtures. Compile the full freestanding payload and PE32+ EFI loader into staging; compile the K64 peer change in native and standalone modes.
5. Handoff only new/modified public source, exact hashes and review points. Exclude input disks, OEM bytes, ROMs, compiled outputs and validation images. Actual guest execution needs an isolated 4 GiB Intel VMX-capable L1, a user-owned installed disk, pinned SeaBIOS, and hashed current K64/runtime inputs. Before the guest gate, every GUI, VMM/channel and app claim remains unverified.

The current native candidate starts the disk's original DOS. The separate DOS replacement step still must load genuine WIN.COM from a volume booted by ShizukuDOS and implement measured INT2F/DOSMGR/resident-state contracts; WIN31SUPPORT currently contains incomplete and overclaiming support paths. Historical source and evidence remain unchanged.
