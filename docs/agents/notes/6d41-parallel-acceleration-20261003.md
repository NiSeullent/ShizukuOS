## Measured source-preparation bottleneck

The completed f903 host closure retained 5,333 descriptors and took 1,409.624s
for 5,326 actual regular native inputs. `Union.io_check` executes every generic
guard at each read/hash checkpoint, while `_project_sources` registers Git HEAD
and whole-working-tree status checks. Every small file has at least three such
checkpoints per full hash pass.

Five read-only measurements on the original frozen f903 worktree found median
HEAD lookup 10.402ms and clean status scan 42.667ms. Its 4,471 committed regular
project blobs (53,521,969 bytes) require 13,419 read checkpoints, or 26,838 Git
processes, per full hash pass. The resulting 712.133s estimate per pass explains
the scale of the observed closure duration. It is a timing-based estimate,
not a profiler result or an accepted production speedup.

The candidate separates explicitly bounded Git namespace checkpoints during
data reads from forced full phase audits. Legacy guard functions still execute
at every checkpoint. Every actual file read retains immediate own descriptor,
path, inode, lease and the shared SIGIO latch. Full final SHA and cleanup checks
remain mandatory. Candidate acceptance requires real temporary Git mutations,
actual Linux FD/lease controls, clock/slow-scan refusal and focused existing
ISO/admission regressions.
