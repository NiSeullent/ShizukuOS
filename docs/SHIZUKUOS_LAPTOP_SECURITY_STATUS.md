# 노트북·계정·보안·개인화 통합 상태

실제 Windows98의 VMM/USER/GDI/Explorer를 유지하는 프로젝트의 추가 구성요소다.
독립 Kernel64 시험이나 별도 네이티브 플랫폼 프리뷰는 Windows98 통합 완료 증거로
사용하지 않는다. 이번 작업은 `codex/laptop-security-iso-fd5c-20261002`에서 진행했다.

`drivers/common/README.md`, `drivers/shz_laptop/README.md`,
`shizukudos/accounts/README.md`, `shizukudos/win64/apps/elevate/README.md`,
`ntwddm/win98/personalization/README.md`에 실제 API와 사용 조건을 기록했다.
정식 ISO 공개 발행은 기존 계약대로 m98.nyase.kr/nginx 담당 c957이 맡는다.
Microsoft 설치 미디어·게스트 디스크·비밀·실제 계정 정보는 추가 ISO에 포함하지 않는다.

검증 기록은 `build/`의 원본 결과와 `docs/agents/status/FD5C2_*.md`에 보존한다.
드라이버의 실제 C 시험21개 실행, 개인화 코어8147/저장104/HTML78 검사,
토큰 권한25사례377검사, 사용자 SID/호출자 일치8사례59검사,
등록 전 샌드박스50검사, 독립 KDF 벡터57개씩을 검증했다.
최종 GUI의 실제 경로97검사는 GCC와 Clang ASan/UBSan에서 각각 통과했다.
GCC·Clang은 각각18개 통합 커널 단위를 컴파일하고 부분 링크를 수행했으며,
외부 런타임 심볼이 남는 부분 링크로 기록했다. 전체 커널/설치 이미지 빌드는 아니다.
계정 생성·대기/종료 수명·인증 자식 실행은 실제 생산 함수와 명시된 경계 어댑터로
확인했다. GCC의 설치된 sanitizer 라이브러리는 없어 해당 GUI 변형은 미실행으로
기록하고, 실제 Clang ASan/UBSan 실행 결과를 사용한다. GUI·통합 컴파일·ISO의
최종 결과는 산출물에 함께 담기는 소스 해시가 맞는 최종 기록으로 판단한다.

전체 계정 시험의 초기120초 및 GUI 컴파일의60/120초 제한 초과는 통과로 바꾸지
않고 원본 기록을 유지했다. 당시 호스트 CPU 대기 압력이 높았으며, 이후 bounded
시험 제한과 GCC/Clang 실행을 기록했다. 수정과 관련 없는 기존 시험을 통과한
소스까지 반복하지 않고, 바뀐 인증·GUI 경로를 최종 소스에서 다시 확인했다.

다른 채팅이 전달한 독립 네이티브 플랫폼 프리뷰
`/root/output/ShizukuDOS-10.0.2-platform-preview.iso`의 실제 SHA256은
`0dc06559e51ab756fd2f79b238c22a0ed436285e24884f2329e3c6661df719f9`와 일치했다.
그 담당자의 BIOS/UEFI7프로필·368검사 및 인증 시나리오16검사 기록은 별도 범위다.
FADA의 실제 Windows98 native11 시험은 실패로 종료됐으며 Windows98 데스크톱,
ShizukuDOS 기반 MS-DOS 대체, 앱·설치·영구 저장 검증을 통과했다고 보고하지 않는다.
