# Laptop, accounts, elevation and personalization

The twelve user requirements authorize implementation and parallel execution without questions. Actual Windows98 remains the product and Explorer remains its visible shell. Work starts at frozen canonical5e2f125, in a separate fd5c worktree. Existing boot/install/private-media custody remains163f/FADA-owned and publication remainsc957-owned.

Account authority runs in Kernel64, never in a caller's DLL. Registration uses a kernel-only bootstrap grant or an authenticated administrator. Passwords use salted PBKDF2-HMAC-SHA256 with600000 rounds, bounded lengths, constant-time comparison and per-account failure throttling. Session identity binds the immutable process creation identity; children inherit before their first thread runs. Logging in does not convert a process with existing handles into a different user. The login broker creates a fresh child instead. Elevation authenticates an administrator for one exact executable/command, launches a fresh process without inherited handles, and does not upgrade the parent. Administrator login normally runs at medium integrity; elevation produces high integrity only for the new child. Account state is initially volatile until a protected on-disk store and native login path pass their own checks. Do not describe volatile account state as persistent protection.

Token rights are enforced before mutation/copyout and duplication cannot amplify granted access. OpenProcess/OpenThread and remote operations must reject another account's processes even if the requested access mask is small. General handle duplication may reduce existing rights; access expansion requires an implemented descriptor check and otherwise fails closed. Sandbox launches have lower integrity and no elevation authority. Windows98 legacy shared address space and kernel driver DMA are not a complete NT isolation boundary.

Drivers reuse existing real PCIe/AHCI/xHCI/WDM cores and add portable common lifecycle plus bounded laptop EC, ACPI fixed-table, HID-over-I2C, sensor and power adapters. Unsupported AML, hardware resource ownership and unverified devices return explicit unsupported errors. Native bindings and hardware tests are separate gates.

Personalization is an additive native Windows98 app using USER32/GDI32 and the existing graphics adapter. Offline ActiveDesktop content provides bounded animation, static wallpaper is a real fallback, and power/suspend/close policy pauses rendering. Preferences and Korean/English settings must survive restart. API errors must remain visible.

ISO output includes only project/public inputs and inspectable receipts. A source/add-on ISO is a valid intermediate artifact but cannot be reported as the completed bootable Windows98 product. No private Microsoft image, credentials, VM image or peer evidence may enter public content. ISO publication belongs exclusively to m98.nyase.kr via the publisher. Existing17GiB native resource reserve is preserved.
