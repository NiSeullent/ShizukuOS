# 5. DOS REENTRANCY — IMPORTANT

Classic DOS APIs are not magically thread-safe.

Therefore PMA must NOT execute arbitrary DOS kernel services concurrently.

Implement a serialized DOS gateway such as:

```text
DOS_GATE
DOS_EXECUTOR
BIG_DOS_LOCK
```

or an equivalent architecture.

Native ShizukuDOS threads may execute concurrently.

Calls into non-reentrant DOS services must pass through the serialization boundary.

Track:

```text
InDOS state
critical errors
PSP ownership
MCB ownership
SFT/CDS accesses
INT 21h
DOS driver chains
callback state
```

Do not introduce concurrency corruption into the DOS compatibility layer.

# 6. UEFI GOP MUST BECOME THE PRIMARY DISPLAY PATH

On UEFI systems:

```text
GOP is the primary display backend.
```

Do NOT use VGA text mode as the default ShizukuDOS console.

During boot:

1. Locate UEFI Graphics Output Protocol.
2. Enumerate every supported GOP mode.
3. Read EDID when available.
4. Determine native/preferred display resolution where possible.
5. Prefer a full-screen high-resolution mode.
6. Map and retain framebuffer information.
7. Survive ExitBootServices.
8. initialize a Shizuku framebuffer console.

Preferred resolution strategy:

```text

```

Do not blindly choose the highest pixel-clock mode if the firmware or framebuffer constraints make it unsafe.

Correctly handle:



# 37. FAILURE BEHAVIOR

If PMA initialization fails:

```text
attempt safe uniprocessor PMA
```

If AP startup fails:

```text
continue on BSP
```

If native GOP resolution fails:

```text
fall back to safe GOP mode
```

If VGA emulator fails:

```text
terminate only the legacy application where possible
```

If PMA9X VxD handshake fails:

```text
Windows 98 should continue without PMA integration
```

A subsystem failure must not automatically turn into a complete system failure.

# 39. DEFINITION OF SUCCESS

Do not use lines-of-code as success criteria.

Success means all of the following work in real execution:

### ShizukuDOS

```text
UEFI boot
GOP full-screen shell
PMA preemptive scheduling
multiple runnable native threads
multiple CPUs when available
thread synchronization
stable storage and input
```

### Legacy DOS

```text
normal DOS text application
legacy VGA application
SVGA/VBE application where supported
virtualized graphics rendered through GOP
```

### Windows 98

```text
ShizukuDOS → WIN.COM → VMM → desktop
existing Win32 applications still execute
VMM bridge loads
VMM↔PMA synchronization works
file I/O remains correct
GUI remains stable
```

### Modern compatibility

At least one real compatibility API path must execute through:

```text
Windows 98 application
→ NT wrapper
→ Shizuku service
→ PMA worker
→ result
→ Windows 98 application
```

before claiming the architecture is integrated.

```text
GOP-FIRST DISPLAY

WINDOWS 98 SEMANTICS PRESERVED
```

Build ShizukuDOS into a modern preemptive execution environment beneath and around Windows 98, rather than attempting to disguise a collection of stubs as a modern operating system.
