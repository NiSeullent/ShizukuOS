# Windows 98 SE의 독자 DLL·GDI 실행과 VxD 진단

2026-09-27, KernelEx가 없는 한글 Windows 98 SE 4.10.2222에서
`NTW32.DLL` 프로브와 `NTWDDMWrapper9x`의 소프트웨어 GDI 프로브가
실제 종료 코드 0으로 통과했습니다. VxD 진단은 종료 코드 30으로 실패했으며,
전체 진단 묶음의 결과도 실패로 보존했습니다.

[원본 로그·해시·종료 코드](NATIVE_GDI_TRIAL.json)는 정지된 게스트 디스크에서
읽었습니다. 13개 파일이 모두 수집됐고, 실행 파일·DLL·VxD·배치 파일은
읽기 전용 진단 CD와 바이트 단위로 일치했습니다. 추출 전후 디스크 해시도
같았습니다. VM은 KVM, 128MiB RAM, 단일 CPU, 네트워크 없는 BIOS 환경입니다.

| 프로그램 | 실제 종료 코드 | 확인한 결과 |
| --- | ---: | --- |
| `NTWPROBE.EXE` | 0 | 기존 독자 Win32 DLL의 정적 import·동적 조회·제한된 동기화·문자 변환 사례 |
| `NTWGPROB.EXE` | 0 | 앱 소유 DIB의 픽셀 계약 검사 128,014회, GDI 화면 그리기 20회, 자원 정리 |
| `NTWVDIAG.EXE` | 30 | 파일 전체 바이트·MZ/LE 검사 통과 후 VxD 장치 열기 실패, Win32 오류 2 |
| `NTWDRUN.EXE` | 1 | 두 성공 프로브 뒤 실패한 VxD 진단에서 중지 |

각 자식 프로세스의 대기 완료, DWORD 종료 코드, 스레드·프로세스 핸들 정리도
감독 프로그램 로그에 있습니다. 화면 캡처에서는 실제 표시된 빨강·파랑·초록·흰색
영역의 내부 픽셀 1,024개를 독립 대조했습니다. 앱 내부의 128,014회 검사는
320×200 DIB 전체 픽셀 비교 두 번과 작업·펜스·기능 계약 검사 14회입니다.
화면 전체가 원본 비트맵과 일치한다고 주장하지 않습니다. 실제 디스플레이는
`BITSPIXEL=1`, `PLANES=4`였고, 앱의 32비트 DIB는 Windows GDI를 거쳐 표시됐습니다.

VxD는 `C:\NTWLAB\NTWRAP9X.VXD`의 9,390바이트가 빌드 산출물과 완전히 같음을
확인한 다음 `\\.\C:\NTWLAB\NTWRAP9X.VXD`를 열었습니다. 절대 경로에서도
오류 2가 재현됐으므로, 첫 시험의 실패를 단순한 검색 경로 문제로 해결했다고
볼 수 없습니다. 이 오류만으로 파일 형식 거부와 초기화 실패를 구별할 수는 없습니다.
후속 [객체 공유 속성 비교 진단](VXD_LOADER_TRIAGE.md)에서도 같은 오류가 재현됐습니다.

그래픽 성공 범위는 독자 렌더러·CPU 복사 펜스·앱 소유 DIB·Windows 98 GDI입니다.
WDDM, Direct3D, GPU 가속, 실제 PCI-E 그래픽 드라이버, 현대 앱 전체 호환성은
아직 검증하지 않았습니다. VxD 커널 실행도 아직 성공하지 않았습니다.
이 결과는 [첫 네이티브 시험](NATIVE_FIRST_TRIAL.md)을 대체해 숨기지 않으며,
새 진단 순서로 그래픽을 실행한 별도 시험입니다.
