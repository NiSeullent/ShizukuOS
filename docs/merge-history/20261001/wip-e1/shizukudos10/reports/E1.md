# E1 — Electron apps on Kernel64's Win64 runtime (branch `wip/e1-electron`)

Vocabulary: `HOST_TESTED` = ran on the Linux host, `GUEST_RUN` = ran inside Kernel64 under QEMU 8.2.2 TCG (there is no `/dev/kvm`
here); these are E1's narrower readings of the labels in `STATUS.md`/`BASELINE.md`. **No Electron app PASSES on Kernel64: every
run below is a FAIL, and the PASS gate is unchanged (marker + exit code 0 + no fault, where a process of the tree killed by the kernel
counts as a fault).** What exists is the harness, the static gap analysis and a measured map of what stops each app.

Two kinds of guest results are kept apart:
- **committed runtime**: this branch's tree as pushed. Its `shizukudos/` runtime files (kernel64, win64) are exactly
  `origin/main` (abc160b) merged with `origin/wip/k4-chromium-run` (bf73d7d); `wip/k5-chromium-dlls` has no commit that main lacks.
  The branch differs from that merge only in E1's own files (docs, `tests/e1_minapp`, the E1 runner, `e1_import_gaps.py`).
  Checked with `git merge-tree` and `git diff --stat`.
- **with E1's proposals**: the same tree plus `e1-proposed/0001`, `0002` and `0003`, built in a scratch worktree (revision
  `0edce4d`, whose tree equals the three patches applied in order; its commit history differs). They are patch files, not commits,
  because `kernel64/`, `win64/kernel32`, `ntdll` and `dlls/` belong to K4/K5 (the lead's assignment). Each patch applies with
  `git apply --check` to the merge `6830ed7` of this branch (runtime files = upstream above).

## Probe apps

`shizukudos/tests/e1_minapp/`:
- `main.js` + `index.html`: the minimal Electron app. It opens a hidden `BrowserWindow` on a local page whose script sets
  `document.title = 'electron-min ' + (6*7)`; main reads the title back with `executeJavaScript`, prints
  `SHZ-E1-MARKER electron-min 42` and calls `app.exit(0)`. Every line is written twice: through `process._rawDebug` (C-level
  stderr, no libuv stream) and through `console.log` (failures of the second are reported, not fatal). An
  `uncaughtException`/`unhandledRejection` handler is installed before anything else, because Electron's own handler shows a
  `TaskDialogIndirect` box that a headless run cannot read and that is fatal here (see wall 14). HOST_TESTED with Electron
  44.5.0 linux-x64 under `xvfb-run`: marker, exit 0 (`--single-process` makes Electron 44 trap with `SIGTRAP` on the host, so the
  guest runs do not use it).
- `nodeprobe.js`: a ladder run as `electron.exe nodeprobe.js` with `ELECTRON_RUN_AS_NODE=1` (Electron's own Node, no
  Chromium). 14 steps, one line each: `SHZ-E1-NODE step N ok: <name>` or `step N FAILED: <name>: <error>`; it continues after a
  failed step and ends with `SHZ-E1-NODE-DONE <n> steps, <k> ok, <m> failed`. HOST_TESTED on the same Linux Electron: 14 of 14.
  The steps: console.log; fs stat/read/write/append/readdir/rename/unlink/rmdir; os; timers+immediates+microtasks; crypto
  random+sha256; zlib; TCP loopback echo; named-pipe echo (`\\.\pipe\`); `child_process.spawnSync`; `dns.lookup`; `http`
  loopback; `child_process.spawn` with stdio pipes; `worker_threads`; `fs.watch`.

## Runner

`shizukudos/tests/run_k64_electron.py` (modelled on `run_k64_chromium.py`): copies the application tree into a FAT32 image under
`build/shizukudos/e1-images/` (`$SHZ_E1_IMAGES` overrides it; never inside git), writes `D:\K64RUN.TXT`, boots the standalone
Kernel64 profile with `shz.noapps shz.autorun=D:\K64RUN.TXT shz.k32trace shz.exctrace` and classifies the serial log. `--app
minimal|default|vscode|node`. The minimal and default apps get `--user-data-dir=D:\e1ud` (wall 15). `--trace-all-syscalls` adds K4's `shz.systrace.all`. A first-chance breakpoint that ends the process is reported with the last LoadLibrary refusal and GetProcAddress miss before it. PASS only for the marker (`SHZ-E1-MARKER electron-min 42`, or `SHZ-E1-NODE-DONE` for `node`) +
exit code 0 + no fault. The result names the furthest point in this order: loader failure, fatal exception, Node/V8 fatal line,
Chromium `FATAL`/`CHECK` line, the marker, first unsupported kernel32 call, the furthest progress line, exit code, timeout;
for `node` it also prints the step matrix. `--env NAME=VALUE` adds environment variables through `env=` lines of the control
file, which needs the kernel change in `0002` (an older kernel ignores them; `--app node` then starts an ordinary Electron).

```
python3 shizukudos/kbuild.py && python3 shizukudos/win64/build.py
python3 shizukudos/tests/run_k64_electron.py --app minimal --tree <electron-v44.5.0-win32-x64>
python3 shizukudos/tests/run_k64_electron.py --app default --tree <electron-v44.5.0-win32-x64>
python3 shizukudos/tests/run_k64_electron.py --app vscode  --tree <VSCodium-win32-x64-1.135.06055>
python3 shizukudos/tests/run_k64_electron.py --app node    --tree <electron-v44.5.0-win32-x64> --env 'USERPROFILE=D:\e1home'
```

The 18: `ws2_32!GetNameInfoW` and 17 kernel32 names: `CancelSynchronousIo, CreateSymbolicLinkW, FillConsoleOutputAttribute,
FillConsoleOutputCharacterW, GetConsoleCursorInfo, GetCurrentPackageFullName, GetErrorMode, GetNumberOfConsoleInputEvents,
GetPackageFamilyName, GetProcessIoCounters, NeedCurrentDirectoryForExePathW, ReOpenFile, ReadConsoleInputW, SetConsoleCursorInfo,
SetConsoleCursorPosition, SetConsoleTitleW, WriteConsoleInputW` (K4 added `RegisterApplicationRestart` since the first
report). All are imported by the executable itself, none by chrome.exe/chrome.dll; they come from Node (libuv's console and
file code) and Electron's app model. With `0001` applied, `startup_chain.py` reports 0 unresolved for both executables.

Totals over all images (load-time + delay-load): Electron + VSCodium 224 distinct unresolved, Chromium (chrome.exe + DLLs) 170,
76 of the 224 not in Chromium's list. libuv's core is already exported by kernel32 (`CreateIoCompletionPort`,
`GetQueuedCompletionStatusEx`, `PostQueuedCompletionStatus`, `SetFileCompletionNotificationModes`, `CancelIoEx`, named pipes,
`ReadDirectoryChangesW`); `CreatePseudoConsole`/`ClosePseudoConsole`/`ResizePseudoConsole` exist nowhere in
`shizukudos/win64` (node-pty's `conpty.node` looks them up with `GetProcAddress`).

Chromium's delay-load failure hook (`chrome/common/win/delay_load_failure_support.cc`, present in Electron) turns **every**
unresolved delay-loaded import into a fatal `CHECK`, so the delay-load columns below are not optional: the first call of any
missing delay-loaded function ends the process.

## Proposals (`e1-proposed/`)

Apply in order with `git apply` to the tree of this branch:
- `0001-functional-electron-node-needs.patch` (≈1000 lines): kernel32 gaps (`CancelSynchronousIo` → `ERROR_NOT_FOUND`, `CreateSymbolicLinkW` /
  `GetProcessIoCounters` → `ERROR_NOT_SUPPORTED`, `ReOpenFile`, package APIs → `APPMODEL_ERROR_NO_PACKAGE`, console cursor/fill/title within
  the existing 80x25 model, `HeapQueryInformation` class 0 = standard heap), fibers (`k32_fiber.c` + `T_K32_FIBER.EXE`; a fiber stack is
  committed in full, FLS callbacks are not run on `DeleteFiber`, documented in the file), `NUL`, `FileAllInformation`, `WriteConsoleW`,
  `\\?\pipe\`, `ws2_32!GetNameInfoW`, `SystemFunction036`. Every function documents what it does here and why.
- `0002-diagnostics.patch`: `env=` lines of the autorun control file, `NtCreateFile` trace with path and status, `ExitProcess`/`TerminateProcess(self)`
  caller trace, failed `CreateFileW`/`CreateNamedPipeW`/`CreateProcessW` traces. Its first version clobbered the caller's last error
  (`k32_trace_on()` calls `GetEnvironmentVariableW`, which sets error 203): `run_k64_standalone.py` failed 5 tests with it; fixed in the
  patch and the suite re-run (0 `[FAIL]`).
- `0003-graphics-and-accessibility-stubs.patch`: `dxgi`, `d3d11`, `d3d12` (an export pinned at ordinal 101 whose real identity is not
  verified), `dcomp`, `dxcore`, `oleacc`, `uxtheme`, each answering "no device/not available" with the failure code Windows uses.
  They only turn a fatal delay-load into an ordinary failure; they add no graphics.
- Verification: see Status (standalone, GUI, `T_K32_FIBER`). The other new functions have no own `T_*.EXE`; their evidence is the ladder and the app runs.
