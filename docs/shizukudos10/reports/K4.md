was written: `chrome.dll+0x3e04cc0`, instruction `mov rax, [rax+0x60]` with `rax = 0xefefefefefefefef`, reached through `mov rax, [rcx]`

(run 21, same binaries, same kernel, same stand-ins, same page) exits 0 while the unsupported `--single-process` mode dies in object
teardown points at Chromium's own single-process shutdown (the browser's and the in-process renderer's singletons share one address

snapshot, no reference run of the same command on Windows exists in this container (Wine 9.0 prints no DOM at all, ELECTRON_TARGET.md
§10.2), and I did not find the object that was freed early. The literal M2 command therefore does **not** pass its exit-code condition.
