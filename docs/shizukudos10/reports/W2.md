## Needed from K5

Interim: `tridentrt.dll` (W2, `shizukudos/win64/trident/comrt`) provides all of the following for the Wine browser
modules, which link it before ole32/oleaut32/shlwapi. Once the Shizuku DLLs have them, tridentrt can shrink.

- ole32: `CoCreateInstance`/`CoGetClassObject` that load an in-process server registered under
  `HKCR\CLSID\{…}\InprocServer32` (the K5 branch `wip/k5-chromium-dlls` has an in-process class table only, not merged
  into the lead yet), `CreateStreamOnHGlobal`, `CreateOleAdviseHolder`, `CreateBindCtx`.
- shlwapi: the `Url*` family and `PathCreateFromUrlW`/`PathIsURLW`, `SHRegOpenUSKeyW` family.
- oleaut32: type libraries (`LoadTypeLib(Ex)`, a real `LoadRegTypeLib`, ITypeLib/ITypeInfo), `DispCallFunc`,
  `CreateStdDispatch`, and `VariantChangeType` for R4/R8/DATE/CY ↔ BSTR.
- comctl32 controls (ReBar, Toolbar, ComboBoxEx, StatusBar, ImageList) and user32 Edit/ComboBox: needed only for the
  iexplore.exe chrome (address bar, toolbar); the WebBrowser control itself does not need them.

## Needed from K4

- Windows without a framebuffer (or at least message-only / hidden windows) in the standalone profile: Wine's urlmon
  and mshtml create windows (`HWND_MESSAGE` notification window, the hidden task window) before any page loads, and
  `CreateWindowExW` fails without a display (`U32_NEED_GFX`). Until then the WebBrowser/mshtml checks can only run in
  `run_k64_gui.py` runs and print SKIP in the standalone run.
- A `WS_CHILD` window whose parent is `GetDesktopWindow()` is refused (`wm_owner_ok`, desktop pid 0); mshtml creates
  its `NsContainer` that way (worked around in W2's code if needed).
- `LoadLibraryExW(LOAD_LIBRARY_AS_DATAFILE)`: type libraries inside PE files are loaded through a wineport patch
  (0200) instead.
