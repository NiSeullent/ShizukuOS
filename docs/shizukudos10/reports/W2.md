## Wineport probe (first data, nothing committed to `modules.json` yet)

Method: a scratch copy of `wineport/modules.json` with `wininet`, `urlmon`, `oleacc`, `jscript`, `msxml3`, `mshtml`,
`ieframe`, `shdocvw` appended (link lists from each Wine `Makefile.in` `IMPORTS`), built with `SHZ_WINEPORT_PROBE=1`
through `wineport/build.py`'s `build(only=...)` against the base build. Results:

| module | first failure |
| --- | --- |
| wininet | link: SSPI (`AcquireCredentialsHandleW`, `InitializeSecurityContextW`, …), `Cert*` chain APIs, shlwapi `Url*`/`PathCreateFromUrlW`/`StrStrIA`, `IdnTo*`, `GetAdaptersAddresses`, `getnameinfo`, `WNet*CachedPassword`, `DosDateTimeToFileTime` |
| urlmon | the generated `.def` has `@ = name @ord` lines for `-noname` exports, which ld rejects (a `winespec.py` case not met by the modules ported so far) |
| oleacc, jscript, mshtml | module-local IDL headers (`oleacc_classes.h`, `jsdisp.h`, `nsiface.h`) are not generated: wineport has no per-module `widl -h` step; jscript also needs `bison` for `parser.y`/`cc_parser.y` |
| msxml3 | needs Wine's `libs/xml2` (+ `libs/xslt`) as static libraries; also `bison`/`flex` for `xslpattern.y/.l` |
| ieframe | link: ole32 `CoCreateInstance`, `CoRegisterClassObject`, `CoRevokeClassObject`, `CreateStreamOnHGlobal`, `CreateOleAdviseHolder`, `OleRegGetUserType`, `StgCreateStorageEx`; shlwapi `PathCreateFromUrlW`, `PathIsURLW`, `UrlApplySchemeW`, `SHRegOpenUSKeyW`/`SHRegQueryUSValueW`/`SHRegEnumUSValueW`/`SHRegCloseUSKey`, `SHSetParentHwnd`; comctl32 `ImageList_LoadImageW`, `ImageList_Destroy`, `CreateStatusWindowW`; shell32 `ShellAboutW`, `ShellExecuteExW`; kernel32 activation contexts, `MulDiv`, `Wow64*FsRedirection`; user32 `DdeGetData` |
| shdocvw | depends on ieframe |
