## Minimal Electron app

`shizukudos/tests/e1_minapp/` (`package.json`, `main.js`, `index.html`): main opens a hidden `BrowserWindow` on the local
page; the page script sets `document.title = 'electron-min ' + (6*7)`; main reads the title back with
`executeJavaScript`, prints `SHZ-E1-MARKER electron-min 42` (console.log + stderr) and calls `app.exit(0)` (non-zero on
every failure path, 15-minute watchdog exits 4).

HOST_TESTED on Linux with Electron 44.5.0 linux-x64 under `xvfb-run`:
- `electron --no-sandbox --disable-gpu --enable-logging=stderr --v=0 shizukudos/tests/e1_minapp` → marker, exit 0.
- packaged layout (app copied to `resources/app`, `electron --no-sandbox --disable-gpu --enable-logging=stderr --v=0
  --no-first-run`) → `SHZ-E1 main: app ready`, `SHZ-E1 renderer console: SHZ-E1 page script ran: electron-min 42`,
  `SHZ-E1-MARKER electron-min 42`, exit 0.
- the same with `--single-process` → `SHZ-E1 main: app ready`, then `Trace/breakpoint trap`, exit 133. Electron 44 does
  not survive `--single-process`, so the guest runs use the normal multi-process model (unlike `run_k64_chromium.py`).
