## Missing Shizuku exports found by the link (adopted toolchain)

`build.py`'s import check (post-link, against the DLLs `win64/build.py` builds, API sets resolved like
`kernel64/apiset.c`) listed these for `jsc.exe`. `webkit/compat/shzwk_missing.c` stands in for each, linked into
jsc.exe only: every stand-in first forwards to the real export through `GetProcAddress` when the runtime has it, so it
retires itself; the fallback is described in the file. They are asked below.

| function | importer in WebKit | Shizuku DLL | fallback in `shzwk_missing.c` |
|---|---|---|---|
| `GetTimeZoneInformationForYear` | `wtf/DateMath.cpp` | kernel32 | `GetTimeZoneInformation` (no per-year rules) |
| `K32QueryWorkingSet` | `wtf/win/MemoryFootprintWin.cpp` | kernel32 | fails, `ERROR_CALL_NOT_IMPLEMENTED` (footprint 0) |
| `CreateMemoryResourceNotification`, `QueryMemoryResourceNotification` | `wtf/win/MemoryPressureHandlerWin.cpp` | kernel32 | an event never set; "not low" |
| `CryptAcquireContextW`, `CryptGenRandom`, `CryptReleaseContext` | `wtf/RandomDevice.cpp` | advapi32 | `ProcessPrng` |
| `__C_specific_handler` (from `crt2.o`, imported from kernel32 by mingw-w64's import library) | CRT startup | kernel32 (Windows forwards it to ntdll) | bound to the Shizuku ntdll export by linking `libntdll.a` first |
| `_AddressOfReturnAddress` | `interpreter/CallFrame.h` (`DECLARE_CALL_FRAME`) | — | not a runtime gap: clang makes it a builtin under `-fms-extensions` (now in the WebKit flags) |

## Needed from K5 (`shizukudos/win64/dlls/`)

1. `ucrtbase.dll` should export `rand_s` and `__C_specific_handler` (Windows' ucrtbase does; mingw-w64 references both).
   Same finding as W3.md §1, which lists more (`_assert`, `_wassert`, `_*_l`, setjmp/longjmp); worked around by W3's
   `deps/shim/shzucrt_fix.c` in the shared toolchain.
2. `advapi32.dll`: `CryptAcquireContextW`, `CryptGenRandom`, `CryptReleaseContext` (WTF's `RandomDevice`; W3 needs the
   same plus the hash functions, W3.md "Needed from K5" 3). On Windows they are advapi32 exports forwarded to
   cryptsp.dll, which the Wine port already builds.

## Needed from K4
